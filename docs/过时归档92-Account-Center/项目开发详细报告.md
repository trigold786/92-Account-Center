## 2. 问题发现阶段

### 2.1 关键问题一：API Gateway代理路径问题

**问题描述**:
所有通过api-gateway代理的请求都返回404错误。

**问题根因**:
在`api-gateway/cmd/main.go`第216行（原始代码）存在：
```go
c.Request.URL.Path = c.Param("path")
```
这段代码在代理请求时会把路径前缀（如`/api/v1/auth/`）去掉，导致后端服务收到的请求路径不正确。

**影响范围**:
所有通过api-gateway代理的端点（10个服务的所有API）。

**发现过程**:
1. 执行集成测试，所有代理请求返回404
2. 检查api-gateway代码，发现路径被修改
3. 移除该行代码后测试通过

**修复方案**:
删除`c.Request.URL.Path = c.Param("path")`，保留原始URL路径。

**修改文件**:
- `api-gateway/cmd/main.go`

---

### 2.2 关键问题二：健康检查不支持HEAD方法

**问题描述**:
Docker的HEALTHCHECK使用`wget --spider`（HEAD方法），但所有服务只支持GET方法访问`/health`端点。

**问题根因**:
所有服务的健康检查路由只注册了GET方法：
```go
r.GET("/health", func(c *gin.Context) { ... })
```

**影响范围**:
所有10个服务的Docker健康检查可能失败。

**修复方案**:
将所有服务的`/health`路由从`r.GET`改为`r.Any`，支持所有HTTP方法（包括HEAD）。

**修改文件**:
- `account-service/cmd/main.go`
- `auth-service/cmd/main.go`
- `sms-email-service/cmd/main.go`
- `kyb-service/cmd/main.go`
- `audit-log-service/cmd/main.go`
- `risk-detection-service/cmd/main.go`
- `session-service/cmd/main.go`
- `email-service/cmd/main.go`
- `device-fingerprint-service/cmd/main.go`
- `api-gateway/cmd/main.go`

---

### 2.3 关键问题三：监控方案不符合SOP要求

**问题描述**:
api-gateway集成了Prometheus，但SOP L5文档明确要求使用VictoriaMetrics。

**问题根因**:
之前的开发人员错误地集成了Prometheus，而非SOP规定的VictoriaMetrics。

**影响范围**:
api-gateway的监控端点，依赖管理。

**修复方案**:
1. 移除Prometheus导入：`github.com/prometheus/client_golang/prometheus/promhttp`
2. 移除`/metrics`端点
3. 移除`/metrics`从公共路径列表
4. 从go.mod/go.sum中移除Prometheus依赖

**修改文件**:
- `api-gateway/cmd/main.go`
- `api-gateway/go.mod`
- `api-gateway/go.sum`

### 3.2 修复过程中的技术挑战

**挑战一：ECS上的Go模块下载慢**

**问题**:
在ECS上执行`go mod download`超时（>120秒）。

**解决方案**:
1. 在本地Windows上交叉编译（GOOS=linux, GOARCH=amd64）
2. 将编译好的二进制复制到ECS
3. 后续通过GitHub推送，让平台自动处理（平台已有编译环境）

**挑战二：SSH密钥管理**

**问题**:
需要临时推送代码到GitHub，但不想长期保留访问权限。

**解决方案**:
1. 生成临时ED25519 SSH密钥对
2. 通过GitHub API添加为部署密钥（有写入权限）
3. 推送代码后立即通过API删除该密钥

**挑战三：auth-service重复代码**

**问题**:
auth-service的NewAuthService函数被声明了两次，导致编译错误。

**解决方案**:
删除重复的声明，保留最新的Redis黑名单版本。

## 7. 给其他团队的建议

### 7.1 部署步骤

1. **获取访问权限**:
   - 联系平台管理员获取SSH密钥
   - 获取ECS地址：101.133.168.46

2. **拉取最新代码**:
   ```bash
   cd /opt/neuro-devsituat-platform/projects/w004-account-center
   git pull origin main
   ```

3. **部署服务**:
   - 使用`docker-compose up -d`
   - 等待健康检查通过

4. **验证部署**:
   - 检查所有服务健康：`http://101.133.168.46:30300/health`（以及其他30301-30309）
   - 运行集成测试：`docs/integration_test.sh`

### 7.2 关键注意事项

1. **代理路径问题**:
   - ❌ 不要再添加`c.Request.URL.Path = c.Param("path")`！
   - ✅ 直接转发原始请求路径

2. **健康检查**:
   - 使用`r.Any("/health", ...)`而非`r.GET("/health")`
   - 支持HEAD方法以兼容Docker HEALTHCHECK

3. **监控方案**:
   - ❌ 不要使用Prometheus
   - ✅ 使用VictoriaMetrics（平台端口20010）

4. **资源登记**:
   - 使用新端口前必须在SOP L5附录A登记
   - 使用新路由前必须在附录B登记
   - 使用新容器名前必须在附录C登记

### 7.3 本地开发环境设置

1. **代理设置**:
   ```powershell
   $env:GOPROXY="https://goproxy.cn,direct"
   $env:GOWORK="off"
   ```

2. **交叉编译（Windows→Linux）**:
   ```powershell
   $env:GOOS="linux"
   $env:GOARCH="amd64"
   $env:CGO_ENABLED=0
   go build -o binary-name cmd/main.go
   ```
