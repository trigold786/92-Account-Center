## 一、VictoriaMetrics监控体系

### 1.1 技术选型说明

原始需求未指定监控技术，实际采用VictoriaMetrics，符合Neuro开SOP一号文规范。

#### 选型对比

| 技术 | 优势 | 劣势 | 最终选择 |
|------|------|------|---------|
| Prometheus | 生态丰富 | 资源消耗大，非SOP标准 | ❌ |
| VictoriaMetrics | 高性能，SOP标准，PromQL兼容 | 相对生态较少 | ✅ |

### 1.2 实现架构

```
┌─────────────────────────────────────────────────────────┐
│                    7个业务服务                            │
│  (account, auth, sms, kyb, audit, risk, session, device)│
│  └─ 每个服务暴露 /metrics 端点 (支持HEAD请求)            │
└────────────────────────┬────────────────────────────────┘
                         │
                         ▼
┌─────────────────────────────────────────────────────────┐
│                  VictoriaMetrics (:20002)               │
│  └─ 采集和存储指标数据                                   │
└─────────────────────────────────────────────────────────┘
```

### 1.3 指标规范

所有服务统一暴露以下指标：

| 指标名 | 类型 | 标签 | 说明 |
|--------|------|------|------|
| http_request_duration_seconds_sum | counter | method, path, status | 请求延迟总和 |
| http_request_duration_seconds_count | counter | method, path, status | 请求计数 |

### 1.4 /metrics端点要求

- **HTTP方法**: 支持GET和HEAD（符合SOP规范）
- **路径**: /metrics
- **内容格式**: Prometheus Text格式
- **无需认证**: 公开端点

## 二、PII数据脱敏中间件技术实现

### 2.1 架构设计

```
┌─────────┐
│ Client  │
└────┬────┘
     │
     ▼
┌─────────────────────────────────────────┐
│ API Gateway                              │
│  ┌─────────────────────────────────────┐ │
│  │ 1. 正常路由到服务                   │ │
│  └─────────────────────────────────────┘ │
│                    │                       │
│                    ▼                       │
│  ┌─────────────────────────────────────┐ │
│  │ 2. 响应捕获中间件                   │ │
│  │    - 缓冲所有写入                   │ │
│  │    - 识别PII字段                   │ │
│  │    - 应用脱敏规则                   │ │
│  │    - 更新Content-Length            │ │
│  │    - 添加X-Desensitized-Header     │ │
│  └─────────────────────────────────────┘ │
└─────────────────────────────────────────┘
                    │
                    ▼
              ┌───────────┐
              │ Client    │
              └───────────┘
```

### 2.2 脱敏规则配置

通过环境变量配置：

```bash
DESENSITIZE_ENABLED=true
DESENSITIZE_FIELDS=phone,email,id_card,bank_card
DESENSITIZE_HEADER_ENABLED=true
```

### 2.3 技术细节

- **缓冲机制**: 使用内存缓冲区保存响应内容
- **性能影响**: 极小（约<1ms延迟）
- **内存管理**: 流式处理，避免大内存占用
- **Content-Length修复**: 重新计算并设置正确长度

## 三、反欺诈黑名单技术实现

### 3.1 数据结构

使用Redis SET存储：

```
# IP黑名单
SET blacklist:ip {ip}

# 设备指纹黑名单
SET blacklist:device {device_fingerprint}

# 用户ID黑名单
SET blacklist:user {user_id}
```

### 3.2 检查流程

```
1. 请求到达
   ↓
2. 检查IP是否在黑名单
   ↓
3. 检查设备指纹是否在黑名单
   ↓
4. 检查用户ID是否在黑名单
   ↓
5. 任一命中则返回403 Forbidden
   ↓
6. 记录到审计日志
```

### 3.3 TTL配置

```bash
# IP黑名单有效期：7天
BLACKLIST_IP_TTL=604800

# 设备黑名单有效期：30天
BLACKLIST_DEVICE_TTL=2592000

# 用户黑名单有效期：永久（可手动移除）
BLACKLIST_USER_TTL=0
```

## 四、推荐返佣引擎技术实现

### 4.1 数据模型

```sql
-- 推荐关系表
CREATE TABLE referral_relationships (
    referrer_id UUID REFERENCES users,
    referee_id UUID REFERENCES users,
    level INTEGER, -- 1=直接推荐, 2=二级推荐, ...
    created_at TIMESTAMP
);

-- 返佣记录表
CREATE TABLE referral_earnings (
    id UUID PRIMARY KEY,
    referrer_id UUID,
    referee_id UUID,
    amount DECIMAL(10,2),
    status VARCHAR(20), -- pending, settled, cancelled
    created_at TIMESTAMP,
    settled_at TIMESTAMP
);

-- 推荐码表
CREATE TABLE referral_codes (
    id UUID PRIMARY KEY,
    user_id UUID REFERENCES users,
    code VARCHAR(50) UNIQUE,
    link VARCHAR(255),
    created_at TIMESTAMP
);
```

### 4.2 返佣计算逻辑

```kotlin
fun calculateCommission(transaction: Transaction): List<Commission> {
    val commissions = mutableListOf<Commission>()

    // 一级返佣：10%
    val level1Referrer = findReferrer(transaction.userId, level = 1)
    if (level1Referrer != null) {
        commissions.add(Commission(
            userId = level1Referrer,
            amount = transaction.amount * 0.10,
            level = 1
        ))
    }

    // 二级返佣：5%
    val level2Referrer = findReferrer(level1Referrer, level = 2)
    if (level2Referrer != null) {
        commissions.add(Commission(
            userId = level2Referrer,
            amount = transaction.amount * 0.05,
            level = 2
        ))
    }

    return commissions
}
```

### 5.2 Color+Theme.swift 设计

```swift
// 16进制颜色初始化支持透明度
extension Color {
    init(hex: String) {
        let hex = hex.trimmingCharacters(in: CharacterSet.alphanumerics.inverted)
        var int: UInt64 = 0
        Scanner(string: hex).scanHexInt64(&int)

        switch hex.count {
        case 8: // ARGB
            let a = Double((int >> 24) & 0xFF) / 255
            let r = Double((int >> 16) & 0xFF) / 255
            let g = Double((int >> 8) & 0xFF) / 255
            let b = Double(int & 0xFF) / 255
            self.init(red: r, green: g, blue: b, opacity: a)
        default: // RGB
            let r = Double((int >> 16) & 0xFF) / 255
            let g = Double((int >> 8) & 0xFF) / 255
            let b = Double(int & 0xFF) / 255
            self.init(red: r, green: g, blue: b)
        }
    }
}
```

## 七、Docker容器化技术实现

### 7.1 Dockerfile最佳实践

```dockerfile
# 多阶段构建
FROM eclipse-temurin:17-jdk-alpine AS builder
WORKDIR /app
COPY . .
RUN ./gradlew build --no-daemon -x test

# 运行阶段
FROM eclipse-temurin:17-jre-alpine
WORKDIR /app

# 创建非root用户
RUN addgroup -S appgroup && adduser -S appuser -G appgroup

# 复制构建产物
COPY --from=builder /app/build/libs/*.jar app.jar

# 切换到非root用户
USER appuser

# 健康检查
HEALTHCHECK --interval=30s --timeout=3s --start-period=10s --retries=3 \
    CMD wget --no-verbose --tries=1 --spider http://localhost:8080/health || exit 1

EXPOSE 8080
ENTRYPOINT ["java", "-jar", "app.jar"]
```
