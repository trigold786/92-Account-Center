- **每项需求必须包含可量化的验收标准**

### 执行顺序原则

1. **依赖前置**：被依赖的任务必须先完成
2. **P0 优先**：Phase 6 全部完成后才进入 Phase 7
3. **同一 Phase 内按风险排序**：高风险任务先做
4. **每个需求完成即验证**：编码→测试→文档标注→下一个

```
│   ├── 新增/修改的微服务代码
│   └── 数据库迁移脚本（Goose up/down）

│   ├── 部署配置（Helm Chart / Docker Compose）
│   ├── CI/CD 流水线配置
│   └── 监控告警配置
├── 测试
│   ├── 单元测试
│   ├── 集成测试
│   └── 测试报告
├── 变更日志
│   └── CHANGELOG_V2.N.md
└── 验收
    └── 验收检查清单（逐项签字）
```

### 阶段完成门禁

每个 Phase 完成前必须通过：

- [ ] 该 Phase 全部需求的单元测试通过
- [ ] 集成测试覆盖该 Phase 的跨服务链路
- [ ] PRD 中该 Phase 全部需求标注"已实现"
- [ ] SSD 中该 Phase 全部技术设计标注"已实现"
- [ ] 阶段产出物清单完整
- [ ] CHANGELOG 已更新
- [ ] Git tag 已打
