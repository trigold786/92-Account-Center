## 一、RFM分析引擎 (Sprint3+)

### 1.1 功能说明

RFM (Recency, Frequency, Monetary) 是一种用于客户价值评估的模型，通过三个维度评估客户：
- **Recency (最近消费)**: 最近一次消费的时间间隔
- **Frequency (消费频率)**: 一定时间内的消费次数
- **Monetary (消费金额)**: 一定时间内的消费总金额

### 1.2 用户故事

作为**产品运营经理**，我希望系统自动计算用户RFM分值并分类，以便制定更精准的营销策略。

作为**APP用户**，我希望在首页看到我的RFM分类，以便了解我的用户价值。

### 1.3 功能要求

| 功能点 | 说明 | 优先级 | 实现状态 |
|--------|------|--------|---------|
| RFM三指标计算 | 自动计算最近消费、消费频率、消费金额 | P0 | ✅ 已实现 |
| 8段客户分类 | 将用户分入8个客户价值分段 | P0 | ✅ 已实现 |
| 营销策略推荐 | 基于分类推荐营销措施 | P1 | ✅ 已实现 |
| 移动端RFM卡片 | 首页展示用户RFM分值和分类 | P0 | ✅ 已实现 |

### 1.4 客户分类定义

| 分段 | RFM代码 | 特征 | 推荐策略 |
|------|---------|------|---------|
| 1. 高价值用户 | 111 | 最近消费频繁、金额高 | VIP特权、专属服务 |
| 2. 重要挽留用户 | 411 | 金额高频率高但最近不来 | 优惠召回、电话关怀 |
| 3. 重要保持用户 | 211 | 金额高频率高但略久 | 保持触达、新品推送 |
| 4. 重要发展用户 | 311 | 金额高频率高但时间不短 | 激活活动、升级引导 |
| 5. 重要价值用户 | 121 | 最近消费金额高 | 保持服务、梯度消费引导 |
| 6. 一般价值用户 | 221 | 金额中等消费中等 | 常规运营、优惠活动 |
| 7. 一般发展用户 | 321 | 各方面中等 | 培养消费习惯 |
| 8. 挽留用户 | 444 | 各方面都低 | 不主动触达，除非必要 |

### 1.5 API接口

| 方法 | 路径 | 说明 |
|------|------|------|
| GET | /api/v1/data/rfm/:user_id | 获取用户RFM数据 |

## 二、PII数据脱敏中间件 (Sprint3+)

### 2.1 功能说明

PII (Personal Identifiable Information) 数据脱敏是保护用户隐私的重要措施，自动对敏感数据进行脱敏处理。

### 2.2 用户故事

作为**合规专员**，我希望系统自动脱敏响应中的敏感数据，以符合个人信息保护法要求。

### 2.3 功能要求

| 功能点 | 说明 | 优先级 | 实现状态 |
|--------|------|--------|---------|
| 自动字段脱敏 | 识别并脱敏敏感字段 | P0 | ✅ 已实现 |
| 可配置规则 | 支持自定义脱敏规则 | P1 | ✅ 已实现 |
| 响应头标识 | X-Desensitized-Header标识脱敏字段 | P0 | ✅ 已实现 |
| Content-Length修复 | 修复脱敏后的Content-Length头 | P1 | ✅ 已实现 |

### 2.4 脱敏规则

| 字段类型 | 脱敏方式 | 示例 |
|---------|---------|------|
| 手机号 | 中间4位替换为**** | 138****1234 |
| 邮箱 | @前保留首字母，其余替换为* | a*****@example.com |
| 身份证号 | 中间8位替换为******** | 110***********1234 |
| 银行卡号 | 中间12位替换为************ | 6225************1234 |
| 密码 | 完全替换为*** | *** |

### 2.5 合规要求

符合以下法规要求：
- 《个人信息保护法》（PIPL）
- 《网络安全等级保护三级》
- GDPR（若需要）
