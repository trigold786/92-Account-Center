### 2.3 注意事项 ⚠️

| 问题 | 说明 |
|------|------|
| 端口冲突 | 本地已有 nce-postgres(5432) 和 nce-redis(6379) 运行中。  
我们的 docker-compose 将内部5432/6379映射到主机20002/20003，**不与 nce 项目冲突**，但需注意不能同时用标准端口启动 PostgreSQL |
| 平台仅2vCPU | 生产级部署需要至少4核，当前2核平台适用于开发和 UAT，不建议用于高负载测试 |
| 平台磁盘59GB | Docker镜像、日志、数据库备份会快速消耗空间，需定期清理 |
| 4个已有容器在运行 | nce-postgres, nce-redis, nce-api, config-service 占用资源，启动 w004 项目前确认资源充足 |

## 3. w004 项目部署配置

### 3.1 端口分配

根据 SOP L5，w004 项目分配端口段 **30300-30399**：

| 服务 | 端口 | 容器名 | 说明 |
|------|------|--------|------|
| api-gateway | 30300 | api-gateway | 入口网关，含 /metrics (Prometheus) |
| account-service | 30301 | account-service | 用户注册/密码/注销 |
| auth-service | 30302 | auth-service | 登录/JWT/Redis黑名单 |
| sms-email-service | 30303 | sms-email-service | 多云短信+SMTP邮件 |
| kyb-service | 30304 | kyb-service | 企业认证/SM4加密 |
| audit-log-service | 30305 | audit-log-service | 审计日志/Redis Streams消费 |
| risk-detection-service | 30306 | risk-detection-service | 风险检测 |
| session-service | 30307 | session-service | 会话管理 |
| email-service | 30308 | email-service | OTP/Magic Link |
| device-fingerprint-service | 30309 | device-fingerprint-service | 设备指纹 |
| db-migrate | — | db-migrate | 一次性数据库迁移(Goose) |

### 3.2 依赖关系

```
┌──────────────┐
│  db-migrate  │──(一次性)──▶│ PostgreSQL │
└──────────────┘             │  (20002)   │
                             └─────┬──────┘
                                   │
          ┌───────────┐     ┌──────┴───────┐     ┌───────────┐
          │  account  │────▶│   sms-email  │     │   auth    │
          │  (30301)  │     │   (30303)    │     │  (30302)  │
          └───────────┘     └──────────────┘     └─────┬─────┘
                                                        │
          ┌───────────┐                                 │
          │   Redis   │─────────────────────────────────┘
          │  (20003)  │──▶ session(30307), email(30308), audit(30305)
          └───────────┘
```

### 3.3 凭证引用

| 服务 | 所需凭证 | 来源 |
|------|----------|------|
| sms-email-service | ALIYUN_ACCESS_KEY_ID/SECRET | .env |
| auth-service | JWT_ACCESS_SECRET, JWT_REFRESH_SECRET, REDIS_ADDR | .env + 平台Redis(20003) |
| email-service | SMTP_USERNAME, SMTP_PASSWORD | .env |
| api-gateway | JWT_SECRET | .env |
| audit-log-service | REDIS_ADDR (Redis Streams) | 平台Redis(20003) |

## 4. 所需环境变量

```bash
# 必需（无默认值）
ALIYUN_ACCESS_KEY_ID=     # 写权限的阿里云Key
ALIYUN_ACCESS_KEY_SECRET=
SMTP_USERNAME=
SMTP_PASSWORD=

# 必需（有默认值，建议修改）
JWT_SECRET=change-me-to-random-64-chars
JWT_ACCESS_SECRET=change-me-to-random-64-chars
JWT_REFRESH_SECRET=change-me-to-random-64-chars
REDIS_ADDR=redis:6379           # auth/audit 共享平台Redis

# 可选（有默认值）
AUDIT_MQ_TYPE=redis             # redis 或 kafka
KAFKA_BROKERS=localhost:9092    # 仅 AUDIT_MQ_TYPE=kafka 时需要
```

## 5. 启动步骤

```bash
# 1. 配置凭证
cp .env.example .env
# 编辑 .env 填写真实凭证

# 2. 执行数据库迁移（首次部署）
docker compose run --rm db-migrate

# 3. 构建并启动（使用平台基础设施）
docker compose up -d

# 4. 验证所有服务健康
curl http://localhost:30300/health
curl http://localhost:30301/health
curl http://localhost:30302/health
# ... 逐一验证11个服务

# 5. 验证 Prometheus 指标端点
curl http://localhost:30300/metrics | head -20
```
